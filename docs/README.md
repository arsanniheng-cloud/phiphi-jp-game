# จป.ซัน แห่งเกาะพีพี — คู่มือโปรเจกต์

เกมจำลองงาน **จป.วิชาชีพ** ในรีสอร์ตริมอ่าวบนเกาะพีพี มีพนักงาน 204 คน 12 แผนก แขกหมุนเวียนตามฤดูกาล
และ NPC ทุกคนจำได้ว่าผู้เล่นเคยทำอะไรกับเขา

> ตัวละครทั้งหมดเป็นชื่อสมมติ ผังรีสอร์ตอิงลักษณะอ่าวบนเกาะพีพี (หน้าผาหินปูน อ่าวน้ำใส ท่าเรือ) ไม่ใช่ผังจริงของรีสอร์ตใด

---

## 1. วิธีเปิดเกม

- **ผ่านเว็บ (แนะนำ):** เปิดลิงก์ของเกมด้วย Chrome, Edge หรือ Safari ได้ทั้งคอมและมือถือ
- **จากไฟล์ในเครื่อง:** ดับเบิลคลิก `index.html` เล่นคนเดียวได้โดยไม่ต้องต่อเน็ต (ถ้าไม่มีเน็ต ตัวอักษรจะใช้ฟอนต์ของเครื่องแทน Sarabun)

## 2. โหมดผู้เล่น

หน้าแรกเลือกได้ 3 แบบ:
- **👤 เล่นคนเดียว**
- **👥 เล่นกับเพื่อน (2–4 คน เครื่องเดียวกัน)** เลือกจำนวนคนและตั้งชื่อ จป. ของแต่ละคนได้
- **🌐 เล่นออนไลน์ ต่างเครื่อง (สูงสุด 4 คน)** คนละที่ คนละ WiFi ได้ (ดูหัวข้อ 2.1)

| ผู้เล่น | เดิน | โต้ตอบ | วิ่ง |
|---|---|---|---|
| P1 (เสื้อกั๊กส้ม) | W A S D หรือคลิกเมาส์ | E | Shift ซ้าย |
| P2 (เสื้อกั๊กฟ้า) | ลูกศร | Enter | Shift ขวา |
| P3 (เสื้อกั๊กเขียว) | จอยเกม 1: ก้านซ้าย/ปุ่มทิศ | ปุ่ม A | ปุ่ม B |
| P4 (เสื้อกั๊กม่วง) | จอยเกม 2 | ปุ่ม A | ปุ่ม B |

- กล้องจะซูมออกให้เห็นทุกคน และผู้เล่นเดินห่างกันได้ไม่เกินระยะที่กล้องยังเห็นครบ
- NPC จำแยกว่า จป. คนไหนทำอะไร (เช่น "ที่พี่ปลาสอนเรื่อง...") ความทรงจำทุกแถวมี `player_id`
- จบวันจะมีตาราง "ผลงานวันนี้แยกรายคน" (พบจุดเสี่ยง แก้ไข คุยสอน PTW สอบสวน)
- ฐานข้อมูลรองรับผู้เล่นได้ไม่จำกัดผ่านตาราง `players`

### 2.1 เล่นออนไลน์ต่างเครื่อง
1. คนหนึ่งกด **สร้างห้องใหม่** เกมจะแสดงรหัสห้อง 6 ตัว (เช่น `JPUY29`) คนนี้เป็น **เจ้าของห้อง**
2. ส่งลิงก์เกม และรหัสห้องให้เพื่อน เช่น ทาง LINE
3. เพื่อนเปิดลิงก์ → **เล่นออนไลน์ ต่างเครื่อง** → ใส่ชื่อและรหัสห้อง → **เข้าร่วม**

วิธีทำงาน:
- เครื่องเจ้าของห้องรันโลกของเกมทั้งหมด (NPC จุดเสี่ยง เวลา) และบันทึกเกม เจ้าของห้องจึงต้องเปิดเกมค้างไว้
- เครื่องอื่นส่งตำแหน่งตัวเอง และส่งคำขอเมื่อคุย/ตรวจ/อนุมัติ ให้เจ้าของห้องตัดสิน ทุกคนจึงเห็นผลตรงกัน
- เปิดหน้าต่างคุยหรือตรวจแล้ว เวลาในเกมยังเดินต่อ (ไม่หยุดเหมือนเล่นคนเดียว) จบวันแล้วเจ้าของห้องเป็นคนกดเริ่มวันใหม่
- เชื่อมต่อแบบ WebRTC ผ่านบริการนัดพบสาธารณะของ PeerJS (ไลบรารี `vendor/peerjs-1.5.5.min.js`)
  ถ้าเครือข่ายบล็อกการเชื่อมต่อตรง จะผ่านเซิร์ฟเวอร์ TURN ของ PeerJS แทน ส่วน WiFi ที่ป้องกันเข้มมาก (บางบริษัท) อาจเชื่อมไม่ได้

### 2.2 ความปลอดภัย
- ข้อมูลทุกชิ้นที่รับจากเครื่องอื่นถูกตรวจชนิด ช่วงค่า และความยาวก่อนใช้ คำขอที่ไม่รู้จักจะถูกปฏิเสธ (`js/net.js`, `sanitizeSnap` ใน `js/sim.js`)
- ข้อความทุกอย่างที่แสดงบนหน้าจอผ่านการ escape และหน้าเว็บมี Content Security Policy ให้รันสคริปต์ได้เฉพาะไฟล์ของเกม
- เจ้าของห้องจำกัดความถี่คำขอของแต่ละคน
- **ข้อควรระวังสำหรับผู้เล่น:** ใครมีรหัสห้องก็เข้าได้ อย่าโพสต์รหัสในที่สาธารณะ · การเชื่อมต่อแบบ P2P ทำให้เครื่องในห้องเดียวกันเห็น IP ของกันและกัน
  จึงควรเล่นกับคนที่รู้จัก · อย่าใส่ข้อมูลส่วนตัวจริงในชื่อผู้เล่น

## 3. วิธีเล่นโดยย่อ

| ปุ่ม | หน้าที่ |
|---|---|
| W A S D / ลูกศร | เดิน (กด Shift วิ่ง) หรือคลิกที่พื้นเพื่อเดินไป |
| E / Enter / Space | คุยกับพนักงาน ตรวจจุดเสี่ยง พิจารณา PTW |
| Tab | รายชื่อพนักงานแยกแผนก |
| L | สมุดบันทึก (เหตุการณ์ จุดเสี่ยงค้าง/CAR สถิติ) |
| P | ใบอนุญาตทำงาน (PTW/JSA) |
| M / Esc | เมนู: บันทึก โหลด ส่งออก JSON/SQL สลับฤดูกาล |
| + / − หรือล้อเมาส์ | ซูม |

กลไกหลัก:
- **จุดเสี่ยงซ่อนอยู่** จนกว่าจะเดินไปเห็นเอง หรือมีพนักงานที่ไว้ใจผู้เล่นมาแจ้ง (📢) วงสีขาวรอบป้ายคือเวลาก่อนเกิดเหตุ
- **การตัดสินใจ 4 แบบ** หยุดงาน / คุยสอน / ออก CAR / ปล่อยไว้ แต่ละแบบเหมาะกับปัญหาต่างกัน (อุปกรณ์ พฤติกรรม หรือสภาพพื้นที่) และเกมอธิบายเหตุผลทุกครั้ง
- **เกือบเกิดอุบัติเหตุ (near miss)** จุดเสี่ยงที่หมดเวลาครั้งแรกอาจเป็นแค่เกือบเกิดเหตุ ทุกคนรู้ แล้วได้โอกาสแก้อีกรอบ
- **ความทรงจำ NPC** ทุกการกระทำถูกบันทึกเป็นความทรงจำ มีคะแนนอารมณ์และความสำคัญ NPC เล่าต่อให้เพื่อน (ข่าวลือ) และนำมาพูดถึงเมื่อเจอกันอีก
- **PTW** งานร้อน งานที่สูง งานไฟฟ้า ต้องขอใบอนุญาต ไปตรวจหน้างานก่อนอนุมัติจะปลอดภัยที่สุด ถ้ารอเกิน 3 ชั่วโมง ช่างอาจเริ่มงานเอง
- **ฤดูกาล** ไฮซีซัน (พ.ย.–เม.ย.) แขกเต็ม งานบริการเร่ง · โลว์ซีซัน (พ.ค.–ต.ค.) มรสุม คลื่น 3 เมตร งานซ่อมบำรุงเยอะ
- **กลางคืน** มองเห็นจุดเสี่ยงได้ใกล้ลง
- **สอบสวนอุบัติเหตุ** เลือกสาเหตุหลักให้ถูก (สภาพไม่ปลอดภัย / การกระทำไม่ปลอดภัย / การจัดการพื้นที่)
- **แพ้** เมื่อบาดเจ็บถึงขั้นหยุดงานครบ 3 ครั้ง หรือความน่าเชื่อถือ จป. เหลือ 0

## 5. ภาพ 3 มิติจาก Blender

อาคาร ต้นไม้ ของตกแต่ง และเรือ สร้างเป็นโมเดล 3 มิติด้วยสคริปต์ แล้วเรนเดอร์ด้วย Cycles (แสงแดด เงา ลายกระเบื้อง หลังคามุงจาก ช่อฟ้าสีทอง)
ถ้าลบโฟลเดอร์ `assets/sprites` เกมจะกลับไปใช้ภาพที่วาดด้วยโค้ดเองโดยอัตโนมัติ

- ใช้ Blender 5.2 ขึ้นไป (รุ่น portable ไม่ต้องติดตั้งก็ได้)
- เรนเดอร์ใหม่ทีละชุด (แนะนำครั้งละไม่เกิน 4 ชิ้น):
  ```
  blender.exe -b --factory-startup -P tools/blender/render_assets.py -- --only b_lobby,tree_palm_0 --samples 40
  ```
  ชื่อภาพ: `b_<id อาคาร>` · `tree_<ชนิด>_<เลข>` · `prop_<ชนิด>_<เลข>` · `boat_longtail_<สี>` · `boat_speedboat`
- ขนาดอาคารอ่านจาก `data/locations.js` อัตโนมัติ ถ้าย้ายหรือเปลี่ยนขนาดอาคาร ให้เรนเดอร์ภาพอาคารนั้นใหม่
- หมายเหตุเฉพาะเครื่องของผู้พัฒนาอยู่ใน `docs/LOCAL-NOTES.md` (ไม่อัปโหลดขึ้นเว็บ)

## 6. ฐานข้อมูล

### 6.1 ตาราง (ตาม `db/schema.sql`)

ต่อยอดจากโครงสร้างที่ออกแบบไว้ (players, resort_npcs, npc_memories, tourist_seasons, dynamic_tourists,
safety_incidents, jsa_permitting_logs) และเพิ่มตารางที่จำเป็น

| ตาราง | เก็บอะไร | มาจาก |
|---|---|---|
| `players` | จป. ผู้เล่น + คะแนนความน่าเชื่อถือ | `data/players.js` |
| `departments` | 12 แผนก + กลุ่มตาม ENUM เดิม (`department_group`) | `data/departments.js` |
| `locations` | จุดทำงาน/จุดเกิดเหตุ พร้อมพิกัด | `data/locations.js` |
| `buildings` | อาคารบนแผนที่ | `data/locations.js` |
| `resort_npcs` | พนักงาน 204 คน นิสัย ความไว้ใจ การปฏิบัติตามกฎ | `data/npcs.js` + สถานะจากการเล่น |
| `npc_memories` | ความทรงจำ (หมวด อารมณ์ −100..100 ความสำคัญ 1–5 วันในเกม) | เกิดระหว่างเล่น |
| `tourist_seasons` | ไฮ/โลว์ซีซัน คลื่น สภาพอากาศ จำนวนแขก | `data/config.js` |
| `dynamic_tourists` | แขกที่พักอยู่ สัญชาติ พฤติกรรมเสี่ยง วันเข้า-ออก | เกิดระหว่างเล่น |
| `hazard_types` | ประเภทจุดอันตราย ความรุนแรง วิธีที่ดีที่สุด เหตุผล | `data/hazard_types.js` |
| `safety_incidents` | จุดเสี่ยงที่พบ เกือบเกิดเหตุ อุบัติเหตุ การแก้ไข สาเหตุ | เกิดระหว่างเล่น |
| `jsa_permitting_logs` | ใบอนุญาตทำงาน การตรวจหน้างาน ผลอนุมัติ | เกิดระหว่างเล่น |
| `day_reports` | สรุปผลรายวัน (ใช้ทำกราฟ) | เกิดระหว่างเล่น |

สิ่งที่เปลี่ยนจากฉบับเดิม:
1. แผนกแยกเป็นตาราง `departments` เพราะ ENUM เดิมขาดครัว สปา สวน ส่วนหน้า และ รปภ. แต่ยังเก็บค่ากลุ่มเดิมไว้ในคอลัมน์ `department_group`
2. หมวดความทรงจำเพิ่ม `recognition` (ชมเชย) `training` (อบรม) และ `rumor` (ข่าวลือที่ได้ยินจากเพื่อน)
3. `safety_incidents.incident_type` เพิ่ม `electrical` `fall_from_height` `injury`
4. ตารางหลักใช้ id จากเกมโดยตรง ไฟล์ที่ส่งออกจากเกมจึงนำเข้าได้ทันที

### 6.2 การบันทึกเกม
- บันทึกอัตโนมัติทุกครั้งที่จบวัน และกด "บันทึกเกม" ในเมนูได้
- เก็บใน **IndexedDB ของเบราว์เซอร์** (ถ้าใช้ไม่ได้จะใช้ localStorage) ใช้ได้เฉพาะเครื่องและเบราว์เซอร์นั้น
- กด "ส่งออกข้อมูล JSON" เพื่อเก็บสำรองหรือย้ายเครื่อง แล้วใช้ "นำเข้าไฟล์ JSON" ในเครื่องใหม่

### 6.3 นำเข้า MySQL ใน XAMPP
1. เปิด XAMPP Control Panel → Start **MySQL**
2. เข้า `http://localhost/phpmyadmin` → แท็บ **Import**
3. นำเข้า `db/schema.sql` ก่อน (สร้างฐานข้อมูล `ehs_resort_island`) ⚠️ ไฟล์นี้ลบแล้วสร้างตารางใหม่ทุกครั้ง
4. นำเข้า `db/seed.sql` (ข้อมูลตั้งต้น) **หรือ** ไฟล์ `.sql` ที่กด "ส่งออก SQL" จากในเกม (ข้อมูลหลังเล่น)

ทดสอบแล้วกับ MariaDB 10.4 ภาษาไทยแสดงถูกต้อง

ตัวอย่างคำสั่งวิเคราะห์หลังนำเข้า:
```sql
-- อุบัติเหตุแยกตามแผนก
SELECT d.short_name, COUNT(*) AS n
FROM safety_incidents s JOIN hazard_types h ON h.id = s.hazard_type_id
JOIN departments d ON d.id = h.department_id
WHERE s.injury_level IS NOT NULL GROUP BY d.id ORDER BY n DESC;

-- ความทรงจำสำคัญ 3 อันดับแรกของ NPC แต่ละคน (Top-K สำหรับส่งเข้า LLM)
SELECT npc_id, memory_text, importance_level, emotional_impact
FROM npc_memories WHERE npc_id = 1 ORDER BY importance_level DESC, game_day DESC LIMIT 3;
```

| จำนวนคนต่อแผนก (ตัวเลขตอนนี้เป็นค่าสมมติ) | `data/departments.js` แล้วแก้ `DEPTS` ใน `tools/generate_npcs.py` ให้ตรงกัน และรันสคริปต์ใหม่ |

```
python -c "import runpy; runpy.run_path(r'tools/generate_npcs.py', run_name='__main__')"
```

## 9. แนวทางต่อยอด
1. **NPC คุยด้วย AI จริง** ส่ง `personality_prompt` + ความทรงจำ Top-K ของ NPC เข้า LLM (มีค่าใช้จ่ายต่อการคุย ต้องมี API key)
2. **เชื่อม MySQL ผ่าน PHP API บน XAMPP** ให้หลายเครื่องใช้ข้อมูลชุดเดียวกัน
3. **ตัวละครจาก Blender** ตอนนี้อาคาร ต้นไม้ และเรือเป็นภาพ 3 มิติแล้ว ตัวละครยังวาดด้วยโค้ด ขั้นต่อไปคือทำโมเดลคนพร้อมท่าเดินแล้วเรนเดอร์เป็นภาพ
4. **เล่นต่างเครื่องผ่านอินเทอร์เน็ต** ตอนนี้ใช้ WebRTC ผ่าน PeerJS แล้ว ถ้าเครือข่ายบางแห่งเชื่อมไม่ได้ ค่อยเพิ่มเซิร์ฟเวอร์เกมกลาง (WebSocket) แยกต่างหาก
5. ใส่จำนวนพนักงานจริงต่อแผนก และจุดอันตรายจากผลประเมิน ปอ.1/ปอ.2 ของรีสอร์ต
