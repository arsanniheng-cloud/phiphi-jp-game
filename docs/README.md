# จป.ซัน แห่งเกาะพีพี — คู่มือโปรเจกต์

เกมจำลองงาน **จป.วิชาชีพ** ในรีสอร์ตริมอ่าวบนเกาะพีพี มีพนักงาน 204 คน 12 แผนก แขกหมุนเวียนตามฤดูกาล
และ NPC ทุกคนจำได้ว่าผู้เล่นเคยทำอะไรกับเขา

> ตัวละครทั้งหมดเป็นชื่อสมมติ ผังรีสอร์ตอิงลักษณะอ่าวบนเกาะพีพี (หน้าผาหินปูน อ่าวน้ำใส ท่าเรือ) ไม่ใช่ผังจริงของรีสอร์ตใด

---

## 1. วิธีเปิดเกม

- **ผ่านเว็บ (แนะนำ):** เปิดลิงก์ของเกมด้วย Chrome, Edge หรือ Safari ได้ทั้งคอมและมือถือ
- **จากไฟล์ในเครื่อง:** ดับเบิลคลิก `index.html` เล่นคนเดียวได้โดยไม่ต้องต่อเน็ต (ถ้าไม่มีเน็ต ตัวอักษรจะใช้ฟอนต์ของเครื่องแทน Sarabun)

### 1.1 เล่นบนมือถือ
- **เดิน:** ลากนิ้วตรงไหนก็ได้บนฉาก (จอยจะเกิดใต้นิ้ว) หรือใช้จอยมุมซ้ายล่าง · **แตะพื้น** = เดินไปตรงนั้น · **สองนิ้วถ่าง/หุบ** = ซูม
- **โต้ตอบ:** แตะคน/ป้ายอันตราย หรือกดปุ่มกลมมุมขวาล่าง (ปุ่มจะบอกว่าจะคุยกับใคร/ตรวจอะไร)
- **แนวตั้ง:** ปุ่มอยู่ที่แถบล่างแบบแอป (แผนที่ · พนักงาน · บันทึก · PTW · แนวนอน · เมนู) ปุ่มเต็มจออยู่ในเมนู
  แถบบนแสดงแบบย่อ แตะแถบบนเพื่อดูค่าเต็มพร้อมชื่อ · ข่าวแสดง 2 ข่าวล่าสุดและหายเองใน 9 วินาที
- **แนวนอน:** กดปุ่ม 🔄 (หน้าแรก หรือแถบปุ่มด้านขวา) แล้วตะแคงมือถือ
  - Chrome บน Android: เกมจะขึ้นเต็มจอและล็อกเป็นแนวนอนให้
  - เบราว์เซอร์ใน LINE/Facebook หรือมือถือที่ปิดหมุนจออัตโนมัติ: เกมหมุนหน้าจอเองทั้งหน้า (Android ดูทิศที่ตะแคงจากเซนเซอร์ แล้วกลับด้านให้ตั้งตรง)
  - กด 🔄 อีกครั้งเพื่อกลับแนวตั้ง · เกมจำค่าที่เลือกไว้ในเครื่อง
- นิ้วใช้ touch events และสั่ง `preventDefault` ทุกครั้ง เพราะเบราว์เซอร์ในแอปบางตัวแย่งท่าลากนิ้วไปเลื่อน/ปิดหน้า ทำให้เดินไม่ได้
- ทดสอบบนคอม: ต่อท้ายลิงก์ด้วย `#touch` จะได้หน้าจอแบบมือถือ

## 2. โหมดผู้เล่น

หน้าแรกเลือกได้ 3 แบบ:
- **👤 เล่นคนเดียว**
- **👥 เล่นกับเพื่อน (2–4 คน เครื่องเดียวกัน)** เลือกจำนวนคนและตั้งชื่อ จป. ของแต่ละคนได้
- **🌐 เล่นออนไลน์ ต่างเครื่อง (สูงสุด 4 คน)** คนละที่ คนละ WiFi ได้ (ดูหัวข้อ 2.1)

| ผู้เล่น | เดิน | โต้ตอบ | วิ่ง |
|---|---|---|---|
| P1 (เสื้อกั๊กส้ม) | W A S D หรือคลิกเมาส์ | E | Shift ซ้าย |
| P2 (เสื้อกั๊กฟ้า) | ลูกศร | Enter | Shift ขวา |
| P3 (เสื้อกั๊กเขียว) | จอยเกม 1: ก้านซ้าย/ปุ่มทิศ | ปุ่ม A | ปุ่ม B |
| P4 (เสื้อกั๊กม่วง) | จอยเกม 2 | ปุ่ม A | ปุ่ม B |

- กล้องจะซูมออกให้เห็นทุกคน และผู้เล่นเดินห่างกันได้ไม่เกินระยะที่กล้องยังเห็นครบ
- NPC จำแยกว่า จป. คนไหนทำอะไร (เช่น "ที่พี่ปลาสอนเรื่อง...") ความทรงจำทุกแถวมี `player_id`
- จบวันจะมีตาราง "ผลงานวันนี้แยกรายคน" (พบจุดเสี่ยง แก้ไข คุยสอน PTW สอบสวน)
- ฐานข้อมูลรองรับผู้เล่นได้ไม่จำกัดผ่านตาราง `players`

### 2.1 เล่นออนไลน์ต่างเครื่อง
1. คนหนึ่งกด **สร้างห้องใหม่** เกมจะแสดงรหัสห้อง 6 ตัว (เช่น `JPUY29`) คนนี้เป็น **เจ้าของห้อง**
2. ส่งลิงก์เกม และรหัสห้องให้เพื่อน เช่น ทาง LINE
3. เพื่อนเปิดลิงก์ → **เล่นออนไลน์ ต่างเครื่อง** → ใส่ชื่อและรหัสห้อง → **เข้าร่วม**

วิธีทำงาน:
- เครื่องเจ้าของห้องรันโลกของเกมทั้งหมด (NPC จุดเสี่ยง เวลา) และบันทึกเกม เจ้าของห้องจึงต้องเปิดเกมค้างไว้
- เครื่องอื่นส่งตำแหน่งตัวเอง และส่งคำขอเมื่อคุย/ตรวจ/อนุมัติ ให้เจ้าของห้องตัดสิน ทุกคนจึงเห็นผลตรงกัน
- เปิดหน้าต่างคุยหรือตรวจแล้ว เวลาในเกมยังเดินต่อ (ไม่หยุดเหมือนเล่นคนเดียว) จบวันแล้วเจ้าของห้องเป็นคนกดเริ่มวันใหม่
- เชื่อมต่อแบบ WebRTC ผ่านบริการนัดพบสาธารณะของ PeerJS (ไลบรารี `vendor/peerjs-1.5.5.min.js`)
  - **คนละ WiFi / 4G**: ถ้าต่อตรงไม่ติดภายใน 10 วินาที เกมจะเชื่อมผ่าน **ทางสำรอง** ให้เอง คือส่งต่อข้อความผ่านเซิร์ฟเวอร์ MQTT สาธารณะทาง WebSocket (`online_relay` ใน `data/config.js`: EMQX, HiveMQ, Mosquitto เจ้าของห้องฟังทุกตัว ผู้ร่วมเล่นใช้ตัวแรกที่ต่อติด)
  - ทางสำรองเข้ารหัสทุกข้อความด้วย AES-GCM กุญแจสร้างจากรหัสห้อง (PBKDF2) ชื่อหัวข้อเป็นค่าแฮชของรหัสห้อง เซิร์ฟเวอร์อ่านข้อมูลไม่ออก และคนที่ไม่รู้รหัสห้องปลอมข้อความไม่ได้ · ส่งภาพรวมโลกราว 4 ครั้ง/วินาที (ต่อตรง 8 ครั้ง) และส่งตำแหน่ง 5 ครั้ง/วินาที
  - เซิร์ฟเวอร์ TURN ฟรีของ PeerJS ปิดไปแล้ว (ตรวจเมื่อ 30 ต.ค. 2569: ชื่อโดเมน `eu-0/us-0.turn.peerjs.com` ไม่มีใน DNS) จึงทำทางสำรองข้างต้นแทน ถ้าภายหลังสมัครบริการ TURN ใส่ได้ที่ `online_turn` (STUN อยู่ที่ `online_stun`)
  - เครื่องที่ใช้ทางสำรองไม่ได้ (เบราว์เซอร์เก่ามาก) จะลองต่อตรงซ้ำ 3 รอบแทน · เจ้าของห้องควรเปิดหน้าเกมค้างไว้ระหว่างรอเพื่อนเข้า
  - ทดสอบ: `#test=netjoin&room=XXXXXX&relay=1` บังคับให้เครื่องที่เข้าห้องใช้ทางสำรอง

### 2.2 ความปลอดภัย
- ทางสำรองผ่านเซิร์ฟเวอร์สาธารณะ: ข้อมูลเข้ารหัสก่อนออกจากเครื่องเสมอ ข้อความที่ถอดรหัสไม่ได้ถูกทิ้ง ผู้ร่วมเล่นทางสำรองเงียบเกิน 20 วินาทีถือว่าหลุด และรับได้สูงสุด 8 การเชื่อมต่อ
- ข้อมูลทุกชิ้นที่รับจากเครื่องอื่นถูกตรวจชนิด ช่วงค่า และความยาวก่อนใช้ คำขอที่ไม่รู้จักจะถูกปฏิเสธ (`js/net.js`, `sanitizeSnap` ใน `js/sim.js`)
- ข้อความทุกอย่างที่แสดงบนหน้าจอผ่านการ escape และหน้าเว็บมี Content Security Policy ให้รันสคริปต์ได้เฉพาะไฟล์ของเกม
- เจ้าของห้องจำกัดความถี่คำขอของแต่ละคน
- **ข้อควรระวังสำหรับผู้เล่น:** ใครมีรหัสห้องก็เข้าได้ อย่าโพสต์รหัสในที่สาธารณะ · การเชื่อมต่อแบบ P2P ทำให้เครื่องในห้องเดียวกันเห็น IP ของกันและกัน
  จึงควรเล่นกับคนที่รู้จัก · อย่าใส่ข้อมูลส่วนตัวจริงในชื่อผู้เล่น

## 3. วิธีเล่นโดยย่อ

| ปุ่ม | หน้าที่ |
|---|---|
| W A S D / ลูกศร | เดิน (กด Shift วิ่ง) หรือคลิกที่พื้นเพื่อเดินไป |
| E / Enter / Space | คุยกับพนักงาน ตรวจจุดเสี่ยง พิจารณา PTW |
| Tab | รายชื่อพนักงานแยกแผนก |
| L | สมุดบันทึก (เหตุการณ์ จุดเสี่ยงค้าง/CAR สถิติ) |
| P | ใบอนุญาตทำงาน (PTW/JSA) |
| M / Esc | เมนู: บันทึก โหลด ส่งออก JSON/SQL สลับฤดูกาล |
| + / − หรือล้อเมาส์ | ซูม |

กลไกหลัก:
- **จุดเสี่ยงซ่อนอยู่** จนกว่าจะเดินไปเห็นเอง หรือมีพนักงานที่ไว้ใจผู้เล่นมาแจ้ง (📢) วงสีขาวรอบป้ายคือเวลาก่อนเกิดเหตุ
- **การตัดสินใจ 4 แบบ** หยุดงาน / คุยสอน / ออก CAR / ปล่อยไว้ แต่ละแบบเหมาะกับปัญหาต่างกัน (อุปกรณ์ พฤติกรรม หรือสภาพพื้นที่) และเกมอธิบายเหตุผลทุกครั้ง
- **เกือบเกิดอุบัติเหตุ (near miss)** จุดเสี่ยงที่หมดเวลาครั้งแรกอาจเป็นแค่เกือบเกิดเหตุ ทุกคนรู้ แล้วได้โอกาสแก้อีกรอบ
- **ความทรงจำ NPC** ทุกการกระทำถูกบันทึกเป็นความทรงจำ มีคะแนนอารมณ์และความสำคัญ NPC เล่าต่อให้เพื่อน (ข่าวลือ) และนำมาพูดถึงเมื่อเจอกันอีก
- **PTW** งานร้อน งานที่สูง งานไฟฟ้า ต้องขอใบอนุญาต ไปตรวจหน้างานก่อนอนุมัติจะปลอดภัยที่สุด ถ้ารอเกิน 3 ชั่วโมง ช่างอาจเริ่มงานเอง
- **ฤดูกาล** ไฮซีซัน (พ.ย.–เม.ย.) แขกเต็ม งานบริการเร่ง · โลว์ซีซัน (พ.ค.–ต.ค.) มรสุม คลื่น 3 เมตร งานซ่อมบำรุงเยอะ
- **กลางคืน** มองเห็นจุดเสี่ยงได้ใกล้ลง
- **สอบสวนอุบัติเหตุ** เลือกสาเหตุหลักให้ถูก (สภาพไม่ปลอดภัย / การกระทำไม่ปลอดภัย / การจัดการพื้นที่)
- **แพ้** เมื่อบาดเจ็บถึงขั้นหยุดงานครบ 3 ครั้ง หรือความน่าเชื่อถือ จป. เหลือ 0

### 3.1 ตัวละครของผู้เล่น
- หน้าแรกมีการ์ด **ตัวละครของคุณ**: ชื่อ เพศ (ชาย/หญิง) ทรงผม สีผิว สีผม สีเสื้อกั๊ก พร้อมภาพตัวอย่างที่หมุนให้ดูรอบตัว
- เกมจำค่าที่เลือกไว้ในเครื่อง (localStorage `jp_me`) ใช้กับเล่นคนเดียว P1 ของโหมดเล่นกับเพื่อน และเล่นออนไลน์ (ส่งหน้าตาให้เจ้าของห้อง แล้วทุกคนเห็นตรงกัน)
- ระหว่างเล่นเปลี่ยนหน้าตาได้ที่ เมนู → **เปลี่ยนหน้าตาตัวละคร** (ชื่อคงเดิม เพราะพนักงานจำชื่อไว้แล้ว)
- ค่าที่รับจากเครือข่ายผ่าน `Sim.cleanLook` (เลขต้องอยู่ในช่วงตัวเลือกเท่านั้น)

### 3.2 แผนงาน ประชุม คปอ. และอบรมพนักงาน (ปุ่ม 📅 แผนงาน)
- **แผนงานประจำวัน** ทุกเช้าเลือก 1 แผน (`data/activities.js` → `daily_focus`)
  | แผน | ผล |
  |---|---|
  | 🔍 เดินตรวจเชิงรุก | มองเห็นจุดเสี่ยงไกลขึ้น 30% พนักงานกล้าแจ้งมากขึ้น |
  | 🦺 รณรงค์ PPE | พนักงานลืมสวม PPE น้อยลงครึ่งหนึ่ง |
  | 🔧 ตรวจเครื่องจักร (PM) | จุดเสี่ยงจากอุปกรณ์ชำรุดลดลง 40% บริการช้าลงเล็กน้อย |
  | 🚨 ซ้อมแผนฉุกเฉิน | ถ้าเกิดเหตุ ความรุนแรงมีโอกาสลดลง บริการสะดุดตอนเช้า |
  | 🛎️ เน้นงานบริการ | ความพร้อมบริการ +10 แต่จุดเสี่ยงเกิดถี่ขึ้น 20% |
- **ประชุม คปอ.** (ต้องมีอย่างน้อยเดือนละครั้ง เกมเตือนเมื่อถึงวันที่ 20 ของเดือนแล้วยังไม่ได้นัด)
  - ถึงเวลา ผู้แทนแผนกละ 1 คนเดินมาที่ล็อบบี้ มีป้ายสีม่วง 🏛️ เดินไปแล้วกด **เริ่มประชุม**
  - วาระที่ 1 ผลการดำเนินงานตั้งแต่ประชุมครั้งก่อน · วาระที่ 2 ข้อเสนอจากผู้แทนลูกจ้าง 3 เรื่อง (เลือกจากแผนกที่มีเหตุ/จุดเสี่ยงมากและความไว้ใจต่ำ)
  - งบความปลอดภัย 100,000 บาท/เดือน ข้อที่อนุมัติลดโอกาสเกิดจุดเสี่ยงนั้นตลอดเกม · เร่งปิด CAR ที่ค้างได้ เรื่องละ 5,000 บาท
  - ผู้แทนจำได้ทั้งเรื่องที่อนุมัติและไม่อนุมัติ · ถ้าไม่ไปตามนัด ความน่าเชื่อถือลดลง
- **อบรมพนักงาน** เลือกแผนก หัวข้อ (9 หัวข้อ เช่น ความปลอดภัยในการทำงานทั่วไป 6 ชั่วโมง ดับเพลิงขั้นต้น CPR LOTO ทำงานบนที่สูง สารเคมี ความปลอดภัยทางน้ำ) วันและเวลา
  - ถึงเวลา พนักงานแผนกนั้นที่อยู่ในกะมารวมที่โรงอาหาร กด **เริ่มอบรม** แล้วตอบคำถามทบทวน 3 ข้อในฐานะวิทยากร
  - **ความปลอดภัยทั่วไป (หลักสูตร 6 ชั่วโมง)** ให้พนักงานเข้าใจพื้นฐาน: ถามครบ 6 ข้อ (ป้ายความปลอดภัย ลำดับการควบคุมอันตราย PPE รายงาน Near Miss การประเมินความเสี่ยง หน้าที่ของลูกจ้าง) ผู้เข้าอบรมอยู่ในห้องอบรม 6 ชั่วโมงในเกม (งานบริการฟื้นช้าลงระหว่างนั้น) ได้ความรู้และความไว้ใจมากกว่าหัวข้ออื่นราว 2 เท่า และลดโอกาสเกิดจุดเสี่ยงทุกประเภทของแผนก 20% ต้องเริ่มไม่เกิน 16:00 น. (ฟิลด์ `hours` `ask` `all` ใน `data/activities.js`)
  - ตอบถูกมาก ความรู้แผนก ความไว้ใจ และการทำตามกฎเพิ่มมาก · จุดเสี่ยงของหัวข้อนั้นในแผนกนั้นเกิดน้อยลงตลอดเกม
  - คำถามและคำอธิบายอิงหลักความปลอดภัยทั่วไป ควรตรวจทานก่อนนำไปใช้สอนจริง
- นัดเวลาใกล้กันไม่ได้ (ต้องห่างกันอย่างน้อย 1.5 ชั่วโมง) · ยกเลิกนัดที่ยังไม่ถึงเวลาได้
- เล่นออนไลน์: เจ้าของห้องเป็นผู้นัดและเปิดประชุม/อบรม ผู้ร่วมเล่นเห็นนัดหมายและเดินไปร่วมฟังได้

### 3.3 ฉากประชุม คปอ. และฉากอบรม (ภาพจำลองแบบเห็นเหตุการณ์)
- กด **เริ่มประชุม / เริ่มอบรม** แล้วจะเห็นภาพจำลองอยู่ด้านบนของหน้าต่าง ตัวละครในภาพคือ **ผู้เข้าร่วมจริง** (พนักงานที่เดินมาที่จุดนัด) และ **ตัวละครของผู้เล่น** ที่เป็นเลขานุการ/วิทยากร (หน้าตาตามที่เลือกไว้)
- **ห้องประชุม คปอ.** (`js/scene_kpo.js`): กรรมการนั่งรอบโต๊ะ กระดานแสดงผลงานวาระที่ 1 · ติ๊กข้อเสนอแล้วผู้แทนแผนกนั้นยกมือเสนอ กระดานแสดงรายการและงบ · ปิดประชุมแล้วลงมติยกมือพร้อมกัน ประทับ "อนุมัติ N เรื่อง"
- **ฉากอบรม 9 หัวข้อ** (`js/scene_train1.js`, `js/scene_train2.js`): ความปลอดภัยทั่วไป (ห้องเรียน จอฉายป้ายความปลอดภัย ลำดับการควบคุมอันตราย ตารางความเสี่ยง) · ดับเพลิง (ลานฝึก ไฟจริง ถังดับเพลิง สามเหลี่ยมไฟ ถัง LPG) · CPR (หุ่นฝึก ตัวนับ 30:2 เครื่อง AED) · LOTO (ตู้เบรกเกอร์ กุญแจ ป้ายห้ามเปิด มิเตอร์) · ทำงานบนที่สูง (นั่งร้าน สายรัดนิรภัย จุดยึด กรวยกั้นพื้นที่) · สารเคมี (ชั้นวางขวด ป้าย GHS ผสมแล้วเกิดก๊าซพิษ) · ทางน้ำ (ท่าเรือ ห่วงชูชีพ ธงแดง) · ยกของ (ท่าย่อเข่า รถเข็น) · ลื่นล้มและทางหนีไฟ
- ทุกคำถามมีฉากสาธิต (ฟิลด์ `show` ใน `data/activities.js`): ก่อนตอบเห็นสถานการณ์ ตอบแล้วผู้เข้าอบรมตอบสนอง (ถูกปรบมือ ผิดงงๆ) และวิทยากรสาธิตวิธีที่ถูกต้องให้ดูเสมอ จบอบรมถ้าผ่านมีกระดาษสีโปรย
- วาดด้วยโค้ดทั้งหมด (canvas) ไม่ต้องโหลดภาพเพิ่ม พิกัดฉาก 640×400 ย่อขยายตามจอ · บนจอใหญ่และมือถือแนวนอนจัดเป็นสองคอลัมน์ (ภาพซ้าย คำถามขวา) · ถ้าไฟล์ฉากโหลดไม่สำเร็จ หน้าต่างยังใช้งานได้ตามปกติ (แค่ไม่มีภาพ)
- เล่นออนไลน์: ผู้ร่วมเล่นเห็นฉากแบบผู้ชม (ใช้พนักงานของแผนกนั้นจากไฟล์ข้อมูลแทนตัวจริง)
- เพิ่มฉากใหม่: `Scene.register('รหัสหัวข้อ', Scene.T.make({ title, bg(c), trainer, slots, caption(S,k), items(S,t,k,push,c) }))` แล้วใส่ `show:` ในคำถามของหัวข้อนั้น

### 6.2 การบันทึกเกม
- บันทึกอัตโนมัติทุกครั้งที่จบวัน และกด "บันทึกเกม" ในเมนูได้
- เก็บใน **IndexedDB ของเบราว์เซอร์** (ถ้าใช้ไม่ได้จะใช้ localStorage) ใช้ได้เฉพาะเครื่องและเบราว์เซอร์นั้น
- กด "ส่งออกข้อมูล JSON" เพื่อเก็บสำรองหรือย้ายเครื่อง แล้วใช้ "นำเข้าไฟล์ JSON" ในเครื่องใหม่

### 6.3 นำเข้า MySQL ใน XAMPP
1. เปิด XAMPP Control Panel → Start **MySQL**
2. เข้า `http://localhost/phpmyadmin` → แท็บ **Import**
3. นำเข้า `db/schema.sql` ก่อน (สร้างฐานข้อมูล `ehs_resort_island`) ⚠️ ไฟล์นี้ลบแล้วสร้างตารางใหม่ทุกครั้ง
4. นำเข้า `db/seed.sql` (ข้อมูลตั้งต้น) **หรือ** ไฟล์ `.sql` ที่กด "ส่งออก SQL" จากในเกม (ข้อมูลหลังเล่น)

ทดสอบแล้วกับ MariaDB 10.4 ภาษาไทยแสดงถูกต้อง

ตัวอย่างคำสั่งวิเคราะห์หลังนำเข้า:
```sql
-- อุบัติเหตุแยกตามแผนก
SELECT d.short_name, COUNT(*) AS n
FROM safety_incidents s JOIN hazard_types h ON h.id = s.hazard_type_id
JOIN departments d ON d.id = h.department_id
WHERE s.injury_level IS NOT NULL GROUP BY d.id ORDER BY n DESC;

-- ความทรงจำสำคัญ 3 อันดับแรกของ NPC แต่ละคน (Top-K สำหรับส่งเข้า LLM)
SELECT npc_id, memory_text, importance_level, emotional_impact
FROM npc_memories WHERE npc_id = 1 ORDER BY importance_level DESC, game_day DESC LIMIT 3;

-- การอบรมแยกแผนก: จัดกี่ครั้ง ผู้เข้าอบรมรวม คะแนนเฉลี่ย
SELECT d.short_name, COUNT(*) AS times, SUM(a.attendees) AS people, AVG(a.score) AS avg_correct
FROM safety_activities a JOIN departments d ON d.id = a.department_id
WHERE a.activity_type = 'training' AND a.status = 'done' GROUP BY d.id;

-- มติ คปอ. และงบที่ใช้ต่อเดือน
SELECT DATE_FORMAT(scheduled_date, '%Y-%m') AS month, SUM(budget_baht) AS baht, GROUP_CONCAT(details_json) AS resolutions
FROM safety_activities WHERE activity_type = 'kpo_meeting' AND status = 'done' GROUP BY month;
```

เปิด `index.html#test=โหมด` โหมด: `day` `night` `storm` `npc` `hz` `lobby` `boh` `pier` `coop` (3 คน) `coop2` `sim` `simcoop`
- `sim` เร่งเวลา 3 วัน สุ่มตัดสินใจทุกแบบ แล้วบันทึก/โหลด และส่งออก SQL เพื่อหาข้อผิดพลาด

### 8.1 ความลื่นบนมือถือ
- ตัวละครแต่ละแบบ (หน้าตา × ทิศ × ท่าเดิน) วาดลงแผ่นภาพรวม (atlas) ครั้งเดียวแล้วใช้ `drawImage` ซ้ำ (`Art.drawPerson` ใน `art.js`) แทนการวาดด้วยโค้ดทุกเฟรม (คนเยอะๆ เคยทำให้กระตุก) · สร้างภาพใหม่ได้ไม่เกิน 8 ภาพต่อเฟรม ที่เหลือวาดด้วยโค้ดไปก่อน จึงไม่สะดุด · หน้าตาที่เหมือนกันใช้ภาพร่วมกัน
- เครื่องช้า: ถ้าเฟรมนานเกิน ~36 ms ต่อเนื่องราว 2 วินาที เกมลดความละเอียดภาพลงทีละ 0.25 (ต่ำสุด 1.0)
- เปิดหน้าต่างค้างไว้ตอนเล่นคนเดียว (โลกหยุดนิ่ง) วาดโลกเบื้องหลังแค่ 1 ใน 3 เฟรม เพื่อให้เหลือแรงวาดฉากประชุม/อบรม
- ผลวัดใน Edge จำลองมือถือที่หน่วงซีพียู 4 เท่า (ฉากล็อบบี้ที่มีคนเยอะ): 11–15 → 45 เฟรม/วินาที (ตัวเลขจริงบนมือถือขึ้นกับรุ่น)

## 9. แนวทางต่อยอด
1. **NPC คุยด้วย AI จริง** ส่ง `personality_prompt` + ความทรงจำ Top-K ของ NPC เข้า LLM (มีค่าใช้จ่ายต่อการคุย ต้องมี API key)
2. **เชื่อม MySQL ผ่าน PHP API บน XAMPP** ให้หลายเครื่องใช้ข้อมูลชุดเดียวกัน
3. **ตัวละครจาก Blender** ตอนนี้อาคาร ต้นไม้ และเรือเป็นภาพ 3 มิติแล้ว ตัวละครวาดด้วยโค้ดสไตล์ชิบิ (หัวโต ตากลม) ถ้าอยากได้ลุคเรนเดอร์ 3 มิติเหมือนอาคาร ให้ทำโมเดลคนใน Blender เรนเดอร์หลายทิศ/ท่าเดินเป็นชั้นภาพ แล้วย้อมสีผิว/ผม/ชุดตอนวาด (ยังต้องใช้โค้ดท่าทางของฉากอบรมแบบวาดเอง)
3.1. **ฝึกปฏิบัติแบบกดเอง** ในฉากอบรม เช่น กดลำดับ PASS ของถังดับเพลิง กดจังหวะ CPR ตอนนี้ฉากสาธิตให้ดูหลังตอบคำถาม

5. ใส่จำนวนพนักงานจริงต่อแผนก และจุดอันตรายจากผลประเมิน ปอ.1/ปอ.2 ของรีสอร์ต
